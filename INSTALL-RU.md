# Автоустановка Kenshi Co-op: хост и гость

Экспериментальная сборка для **двух игроков**: свои отряды и персонажи в интерфейсе, найм к принимающему игроку, раздельные кошельки. В предыдущей версии на двух клиентах прошли 104 основные и 75 дополнительных проверок. Проверки новой сборки, установщика и Porthole описаны отдельно в отчётах этого релиза.

## Что скачать

- Создателю мира — **KenshiCoop-Setup-Host.exe**.
- Подключающемуся другу — **KenshiCoop-Setup-Guest.exe**.

Это два входа в один установщик с разными начальными ролями. Роль можно изменить в окне. Каждый устанавливает игру у себя. Нужна собственная Steam Kenshi: проверенная 1.0.68 либо совместимая 1.0.65. Другие сборки и GOG этим установщиком не поддерживаются.

## Установка

1. Запустите свой EXE. Он найдёт Kenshi по библиотекам Steam. Если игра не найдена, выберите папку с `kenshi_x64.exe` и `data`.
2. Выберите **новую, ещё не существующую папку** для кооператива. По умолчанию она создаётся в `Games` вашего профиля. Нужен объём, сопоставимый с полной игрой, плюс примерно 1 ГБ запаса. Оригинальная установка и её сохранения не изменяются; другие установленные моды и старые сохранения в новую копию не переносятся.
3. Проверьте роль и способ связи. Для **Porthole** выберите `Porthole — UDP через Steam` и прочитайте раздел ниже: у гостя адрес всегда `127.0.0.1`, порт — локальный принятый порт Porthole. Для обычного Steam можно оставить ID друга пустым и обменяться ID в игре через F2. Для прямого UDP гость вводит IPv4 или имя компьютера хоста и порт хоста.
4. Нажмите **Установить**. Установщик скачает примерно 26 МБ с закреплённых релизов GitHub и проверит SHA-256. Если отсутствуют библиотеки C++ x64, он дополнительно скачает официальный пакет Microsoft и предложит Windows запрос прав. Перезагрузка автоматически не выполняется. Если Windows требует перезагрузку, выполните её и повторите установку.
5. После завершения запустите игру через ярлык **Kenshi Co-op Host / Guest** или `KenshiCoop-Play.exe --play` в новой папке. При первом запуске может появиться штатное окно выбора графики Kenshi: выберите Direct3D11 и нажмите OK.

Установщик использует официальный RE_Kenshi 0.3.5 и его патчер, чтобы создать отдельный совместимый исполняемый файл 1.0.65. Игровые EXE, данные и Steam DLL в установщик не включены: они берутся из вашей копии. Игра копируется физически, без hardlink и junction. Существующие папки не перезаписываются. При прерывании незавершённая папка с именем `.kc-...` рядом с выбранной папкой сохраняется для диагностики; после закрытия установщика её можно удалить вручную.

## Первый запуск

### Хост

1. Для новой игры выберите старт **Multiplayer (Wanderer x2)**. Он создаёт два заполненных отряда — для хоста и гостя. Обычный старт с одним персонажем не создаёт персонажа другу автоматически.
2. Для продолжения используйте сохранение из этой кооперативной копии, где уже есть персонажи обоих игроков. Оригинальные сохранения установщик не переносит.
3. Нажмите **F2**, убедитесь, что роль — **HOST**.
4. Для Steam: у обоих запущен Steam; обменяйтесь ID кнопками **Copy my Steam ID** и **Paste friend's Steam ID**. Нужен ID другого игрока на обеих сторонах. Если ввели его в установщике, проверьте отображаемое значение.
5. Включите **Connection → ONLINE** после загрузки мира.

### Гость

1. Запустите свою копию. Создавать новую игру или заранее копировать сохранение хоста не нужно.
2. Прямо из главного меню откройте **F2**. Роль должна быть **JOIN**, способ связи — таким же, как у хоста.
3. Для Steam введите ID хоста, если ещё не ввели. Включите **Connection → ONLINE**. Дождитесь передачи мира и автоматической загрузки.

Для прямого UDP используйте адрес хоста и порт хоста. Внешнее прямое UDP-подключение может требовать настройки роутера/брандмауэра; установщик эти настройки не меняет. Для туннеля Porthole используйте отдельный порядок ниже. Сам выбор способа связи не означает, что соединение уже установлено.

## Porthole — Local Port Sharing

Нужен [официальный Porthole из Steam, приложение 4963920](https://store.steampowered.com/app/4963920/) у обоих игроков. Установщик его не скачивает и не настраивает Steam-друзей автоматически. Кнопка **Porthole** открывает установленное приложение через Steam. Оба игрока выбирают в установщике профиль **Porthole — UDP через Steam**. Внутри Kenshi используется **UDP**: туннель Steam создаёт Porthole.

### Хост

1. Запустите подготовленную кооперативную копию. Создайте мир `Multiplayer (Wanderer x2)` либо загрузите кооперативное сохранение.
2. Откройте F2, проверьте **HOST / UDP**, порт **27800** (или выбранный вами), включите **ONLINE**. Игра начинает слушать UDP-порт.
3. В Porthole создайте закрытое лобби. Добавьте локальный сервис **UDP**, адрес `127.0.0.1`, порт `27800`. Предложите этот порт другу. TCP для KenshiCoop не подходит.
4. Передайте другу код лобби или пригласите его средствами Porthole. Держите Porthole открытым всю игру.

### Гость

1. В Porthole присоединитесь к лобби хоста и примите предложенный **UDP**-порт.
2. Посмотрите **локальный** порт, который Porthole открыл на вашем компьютере. Обычно это `27800`; если порт занят, назначьте другой, например `27801`.
3. В установщике гостя выберите профиль Porthole. Адрес автоматически станет **127.0.0.1**. В поле порта укажите локальный порт Porthole у себя: `27800` или переназначенный `27801`.
4. Запустите свою кооперативную копию, из главного меню откройте F2. Проверьте **JOIN / UDP**, адрес `127.0.0.1` и свой локальный порт. Включите **ONLINE**, дождитесь передачи и загрузки мира.

Пример: хост Kenshi слушает `127.0.0.1:27800`; Porthole гостя переназначил его на `127.0.0.1:27801`; значит в Kenshi гостя нужен порт **27801**. Порт хоста при этом остаётся **27800**. Не вводите публичный IP хоста или Steam ID в UDP-адрес. На разных компьютерах одинаковые локальные порты не конфликтуют. Kenshi-гость использует собственный временный исходящий UDP-порт и не занимает порт слушателя Porthole.

При смене порта в Porthole измените его и в настройках Kenshi. Закрытие Porthole разрывает туннель. Сначала восстановите лобби и принятие порта, затем переподключите Kenshi через F2. Обычный режим Steam в KenshiCoop остаётся отдельным вариантом подключения.

### Обновление и смена подключения без копирования игры

Если уже установлена наша предыдущая сборка, закройте игру, запустите новый установщик и нажмите **Обновить готовую копию**. Выберите отдельную кооперативную папку с `KenshiCoop-install.json`, настройте роль/подключение и нажмите **Сохранить**. Обновляются только мод, запуск и настройки; кооперативные сохранения и игровые данные не копируются заново. Изменяемые файлы сохраняются в `connection-backup-...` внутри этой копии. Не выбирайте оригинальную Steam-папку.

После установки настройки можно открыть файлом **KenshiCoop-Connection.cmd** в кооперативной папке. Там же можно вернуться к обычному UDP или Steam. При возврате профиль Porthole отключается. Для обновления старой DLL нужен доступ к GitHub.

### Сетевой профиль

Профиль включается только при выборе Porthole. Он уменьшает MTU ENet до **1200 байт**, а пакеты состояний персонажей разбивает на группы до 14 записей под этот размер. Это консервативный размер для туннеля, а не заявленный жёсткий предел Porthole. Он уменьшает риск фрагментации и перевода больших пакетов движения в надёжные фрагменты ENet.

Сохранение передаётся порциями до **16 КиБ каждые 50 мс**, с приостановкой подачи при накоплении примерно **64 КиБ** неподтверждённых данных канала сохранений в ENet. Благодаря этому большая передача меньше заполняет очередь перед игровыми командами. Передача мира может занять дольше. Порядок потока и проверка содержимого сохраняются; деньги, инвентари и сохранения передаются надёжно. Каналы игровых событий и сохранения остаются раздельными. Частота сети остаётся прежней, 20 Гц. В обычном UDP/LAN и прямом Steam это ограничение очереди Porthole не включается.

Это не обещание меньшего пинга на любом маршруте. Скорость и задержка зависят от соединения обоих игроков и выбранного Porthole маршрута. Результаты автоматических сетевых тестов и ограничения реального Steam-туннеля указаны в отчёте этого релиза.

Официальные сведения о модели подключения: [страница Porthole](https://porthole.sestudio.org/) и [Steam](https://store.steampowered.com/app/4963920/). Локально исследована версия Porthole 3.0.2; версии приложения могут менять подписи кнопок.

## Сохранения, деньги и отряды

- Новая копия использует собственные папки `save` и `isolated-appdata`. Ярлык очищает унаследованные тестовые переменные и включает раздельные деньги и свои отряды.
- У хоста и гостя отдельные кошельки; персонажи одного игрока используют его общий кошелёк.
- Владелец и деньги сохраняются вместе с миром в `coop_squads.dat` и `coop_wallets.dat`. Не удаляйте эти файлы и не загружайте сохранение старой DLL.
- В старом кооперативном сохранении без sidecar первые два заполненных отряда распределяются хосту и гостю; прежние общие деньги делятся пополам, нечётный остаток получает хост.
- Пустой новый отряд хранит владельца только в текущем сеансе, пока туда не назначен персонаж. Автоматический номер гостевого отряда после загрузки может измениться, состав и владелец сохраняются.
- Роли относятся к фиксированным слотам хоста/гостя, а не аккаунтам Steam. Другой гость получает тот же гостевой слот.

## Если возникла ошибка

- «Неизвестная версия»: сверьте версию Steam и целостность игры. Установщик останавливается на неподдерживаемом хеше, а не меняет EXE наугад.
- «Папка уже существует»: выберите новую папку. Для повторной установки существующие данные автоматически не удаляются.
- «Контрольная сумма не совпала»: пакет не запускается. Закройте установщик и уберите повреждённый файл из `%LOCALAPPDATA%\KenshiCoopSetup\cache`, затем повторите скачивание.
- Нет соединения: проверьте роль, одинаковую сборку/способ связи, ID другого игрока либо адрес/порт. У гостя дождитесь передачи мира. Логи: `KenshiCoop_host.log` / `KenshiCoop_join.log` в новой папке, ошибки загрузчика — `RE_Kenshi_log.txt`.
- Для удаления закройте игру и удалите **только отдельную кооперативную папку** и её ярлык. Сначала сохраните нужные кооперативные сохранения. Microsoft C++ удалять не требуется.

Полная кампания, все сторонние моды и все варианты диалогов/магазинов не проверены. Ранее наблюдалась отдельная нерешённая ошибка фокуса RE_Kenshi. Сохранение по запросу гостя ждёт подтверждения его денег; сохранение самим хостом использует последний полученный баланс гостя и не имеет общего барьера всех покупок/инвентарей.
