Нужна собственная лицензионная Steam Kenshi. Установщик поддерживает исходную Steam1.0.68/1.0.65 и создаёт отдельную совместимую копию; игровые файлы не распространяются. Для имеющейся управляемой копии выберите «Обновить готовую копию». Сохраняются кампании, личный идентификатор и имя игрока; заменяемые файлы резервируются. При обновлении автоподключение выключается: сначала загрузите кампанию, затем включите соединение вручную. Обновиться должны все участники.

## Изменения .5.3

- Исправлены обращения к сохранённому закрытому торговцу при обычном переносе предметов и при создании нового мира.
- Новый мир очищает прежнюю привязку кампании и получает уникальное имя первоначального снимка; старое `coopresume` не перезаписывается.
- Передача сохранения использует неизменяемый снимок. Повторная запись хоста не подменяет файлы уже отправляемого мира; приём проверяет порядок, имена, размеры и CRC.
- После обрыва можно безопасно завершить уже подтверждённую сделку по точному исходному RELEASE, принятому ассортименту и совпавшему инвентарю персонажа. Неизвестный результат незавершённой сделки сохраняет блокировку.
- Ход передачи виден в главном меню и в загруженном мире.
- Установщик1.5.3 поддерживает обновление прежних публичных версий и локальной1.5.2.1 с резервированием и откатом.

Игровая DLL совпадает с проверенной локальной .5.2.1. Ассортимент, деньги и штатное пополнение торговцев, введённые в .5.2, сохранены; подробные условия первого визита и пополнения описаны в инструкции.

## Быстрый порядок игры

1. Хост создаёт новый мир по кооперативному старту из инструкции либо загружает свою последнюю целую кампанию со всеми `coop_*.dat`.
2. После загрузки мира хост включает соединение через F1 → Quick Connect → Connect. Для Porthole выбирается профиль Porthole и предлагается выбранный UDP-порт.
3. Гость принимает подключение Porthole. В моде использует `127.0.0.1` и локальный принятый порт на своём ПК, который может отличаться от порта хоста.
4. Гость подключается из главного меню, ждёт передачи и автоматической загрузки. Отдельный мир ему создавать не нужно.
5. Сохраняет хост после завершения торговли, закрытия торговых окон и подтверждений. Для продолжения не смешивайте файлы разных кампаний.

## Проверки и пределы

Та же DLL прошла **22 проверки с настоящими клиентами** Kenshi Steam1.0.65 x64, два отдельных процесса на одном ПК, loopback ENet с профилем Porthole. Проверены торговля гостя, полное совпадение193записей ассортимента и денег, отдельные кошельки, перенос предмета после закрытия магазина, сохранение/загрузка, новый мир с девятью владельцами0–8 и подключение гостя. Дополнительно прошли **925 проверок** протокола, производственных функций и файловых операций с указанными в отчётах заглушками. Установщик1.5.3 прошёл **155 проверок**, соседний автономный кэш — отдельную проверку.

- Две независимые внешние сети и восемь одновременных нативных гостей в этих проверках не использовались.
- Авария посреди неподтверждённой торговли может требовать перезагрузки последней целой кампании хоста. Автоматически принимать неизвестные изменения небезопасно.
- Отдельная прежняя трасса завершения хоста через ResourceLoader/Logger не имеет установленной причины и не заявляется исправленной.
- Длительная кампания, все магазины, каждый вариант взаимодействия и совместимость со всеми сторонними модами не подтверждены.
